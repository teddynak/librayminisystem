# Lecturer submission checklist

| Required item | Repository location or action |
|---|---|
| Project proposal | docs/reference/project-proposal.docx |
| Requirements specification | docs/reference/requirements-specification.docx |
| System design and UML | docs/system-design.md and docs/system-design.docx; original planning document in docs/reference/system-design-original.docx |
| Complete Java source | src/main/java, src/main/resources, pom.xml |
| Functional application | Build and launch using README; Maven project is the reproducible application delivery |
| Test cases and results | docs/test-results.md, src/test/java and docs/evidence |
| Technical documentation | docs/technical-documentation.md or docs/technical-documentation.docx; docs/setup-guide.md |
| User manual | docs/user-manual.md and docs/user-manual.docx |
| Final project report | docs/final-project-report.md and docs/final-project-report.docx |
| Demonstration and oral presentation | Student performs; use docs/presentation-guide.md |
| Google Drive explanation video | Student records, uploads and submits the real link |

Before submission, run on your own Ubuntu desktop, record actual observations in manual-test-checklist.md, verify that you understand the code and confirm the lecturer's preferred document and archive formats. The system design, technical documentation, user manual and final project report are available in both Markdown and Word formats. Markdown can be read on GitHub, and the Word copies can be downloaded for editing or submission. Export a PDF only if the lecturer requests it. The assignment does not prescribe a particular file format or native installer.

Do not submit target build caches or a database containing real personal information. The development master prompt is reference material, not one of the lecturer's required deliverables. Keep the original planning documents and implemented design together so design changes are clear.
